# BizBoard — backend платформы B2B-объявлений

API-first бэкенд для платформы деловых объявлений малого и среднего бизнеса
(ДНР, ЛНР, Херсонская и Запорожская области). Реализован по ТЗ: разделы 1–3
взяты из исходного документа, разделы 4–10 восстановлены в
[`docs/TZ-restored.md`](docs/TZ-restored.md).

## Возможности

- **Авторизация через Telegram deep-link**: одноразовая сессия входа, JWT
  access-токен на 15 минут, refresh-токен на 30 дней с ротацией и обнаружением
  повторного использования (отзывается всё семейство токенов).
- **Платформенные роли и TOTP**: админ-API доступен только с `mfa=true` в
  access-токене и конкретным платформенным разрешением.
- **Организации**: владелец, сотрудники, кастомные роли с кодами разрешений,
  приглашения на 72 часа, кэш прав в Redis, передача владения.
- **Верификация**: контрольная сумма ИНН (10/12 цифр), телефон через Telegram,
  документы и ручная проверка модератором, три уровня бейджа.
- **Каталог**: дерево до 3 уровней, наследуемые атрибуты, валидация JSONB.
- **Объявления**: 8 типов, черновик → модерация → публикация, лимиты тарифа и
  частного лица, избранное, жалобы, статистика просмотров, продвижение.
- **Поиск**: полнотекстовый (`tsvector`, русский язык), фильтры по категории с
  потомками, типу, региону, цене, атрибутам (`attr.<key>`, `.min`, `.max`).
- **Контакты объявлений видны только авторизованным пользователям.**
- **Админ-API**: пользователи, роли, организации, модерация, жалобы, каталог,
  тарифы, аудит, настройки, сводная статистика.

## Стек

Python 3.12 · FastAPI · Pydantic 2 · SQLAlchemy 2 (async) · PostgreSQL 16 ·
Redis 7 · Alembic · PyJWT · pyotp · pytest + aiosqlite + fakeredis.

## Структура

```text
app/
  core/        конфигурация, БД, Redis, безопасность, ошибки, лимиты, storage
  models/      SQLAlchemy-модели
  schemas/     Pydantic-схемы
  services/    бизнес-логика (auth, организации, каталог, объявления, поиск)
  api/         роутеры FastAPI: /api/v1/* и /api/v1/admin/*
  seed.py      идемпотентный seed ролей, тарифов, категорий и настроек
alembic/       миграции
scripts/       эксплуатационные скрипты
tests/         unit- и integration-тесты
docs/          документация: архитектура, API, БД, безопасность, эксплуатация
```

## Быстрый старт через Docker Compose

```bash
cp .env.example .env
# отредактируйте SECRET_KEY и параметры Telegram
docker compose up --build
```

Контейнер `api` при старте выполняет `alembic upgrade head`, затем
`python -m app.seed` и запускает Uvicorn. API: <http://localhost:8000>,
Swagger: <http://localhost:8000/docs>, health: `/health`, readiness: `/ready`.

## Локальный запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt

cp .env.example .env
# укажите DATABASE_URL и REDIS_URL

alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

Для быстрой проверки без PostgreSQL/Redis можно включить
`AUTO_CREATE_TABLES=true` — таблицы будут созданы при старте, а при
недоступности Redis включится внутрипроцессный кэш. **В production так делать
нельзя**: используйте Alembic и общий Redis.

## Переменные окружения

Все настройки находятся в `.env` (см. `.env.example`). Обязательные в
production:

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | подпись JWT и ключ шифрования TOTP (не короче 32 байт) |
| `DATABASE_URL` | `postgresql+asyncpg://user:pass@host:5432/db` |
| `REDIS_URL` | `redis://host:6379/0` |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_BOT_USERNAME` | username бота без `@` |
| `TELEGRAM_WEBHOOK_SECRET` | секрет заголовка вебхука |

Дополнительно: `SUPERADMIN_TELEGRAM_ID` и `SUPERADMIN_PHONE` создают
суперадмина при seed, `CORS_ORIGINS` задаёт список origin через запятую,
`PRIVATE_ACTIVE_LISTING_LIMIT` — лимит активных объявлений частного лица,
`DEFAULT_LISTING_TTL_DAYS` — срок публикации после одобрения.

## Первый администратор и TOTP

1. Укажите в `.env`:

   ```env
   SUPERADMIN_TELEGRAM_ID=123456789
   SUPERADMIN_PHONE=+79990000000
   ```

2. Выполните `python -m app.seed` — пользователь получит роль `superadmin`.

3. Войдите через Telegram. Обычный access-токен содержит `mfa=false`, поэтому
   админ-API вернёт `403 mfa_required`.

4. Создайте секрет: `POST /api/v1/auth/totp/setup` (только для платформенных
   ролей), добавьте его в приложение-аутентификатор.

5. Подтвердите код: `POST /api/v1/auth/totp/enable` с `{"code": "123456"}`.
   В ответ придут токены с `mfa=true`. Для последующих входов используйте
   `POST /api/v1/auth/totp/verify`.

Без `TELEGRAM_BOT_TOKEN` в dev-окружении доступен скрытый маршрут
`POST /api/v1/auth/telegram/dev-confirm` (только при `DEBUG=true` и
`ENV != production`) — он подтверждает вход без реального бота.

## Telegram webhook

```bash
python -m scripts.set_telegram_webhook https://api.example.com/api/v1/telegram/webhook
```

Вебхук обрабатывает `/start login_<token>` (вход), `/start invite_<token>`
(принятие приглашения) и получение контакта (подтверждение телефона).
Если задан `TELEGRAM_WEBHOOK_SECRET`, запросы без корректного заголовка
`X-Telegram-Bot-Api-Secret-Token` отклоняются.

## Периодические задачи

Просроченные объявления переводятся в `expired`:

```bash
python -m scripts.expire_listings
```

Запускайте по cron каждые 10–15 минут. В production также рекомендуется
ежедневный бэкап PostgreSQL (хранение 14 дней) и мониторинг `/ready`.

## Тесты

```bash
python -m pytest
```

Тесты используют in-memory SQLite и fakeredis, внешние сервисы не нужны.
Покрыты: контрольная сумма ИНН, нормализация телефона, глубина каталога и
наследование атрибутов, полный сценарий «вход → организация → объявление →
модерация → поиск → контакты после входа», роли и приглашения организации,
избранное и жалобы, админ-управление каталогом/тарифами/ролями/пользователями,
обязательность TOTP для админ-API, лимит публикаций частного лица, ротация
refresh-токенов и обнаружение повторного использования.

## Ключевые правила

- Черновик не виден публично; в выдаче только `active` и не истёкшие.
- Публикация проверяет лимит тарифа организации или лимит частного лица.
- После одобрения объявление активно 30 дней; отклонение и блокировка требуют
  причину.
- Контакты не отдаются без авторизации (`contacts_available=false`).
- Нельзя пожаловаться на своё объявление или объявление своей организации.
- Owner организации имеет все права; кастомную роль нельзя удалить, пока она
  назначена; нельзя выдать разрешения, которых нет у выдающего.
- Все изменяющие операции администраторов пишутся в `audit_logs`.
